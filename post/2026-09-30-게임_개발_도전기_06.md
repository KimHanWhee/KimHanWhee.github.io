## 왜 서버가 필요했나

가챠를 만들려다 막혔다.

> **확률을 클라이언트가 굴리면 안 된다.**

게임 안에서 난수를 돌리면 마음만 먹고 뜯어볼 수 있다. 레전드 확률 3%를 100%로 바꾸는 게 어렵지 않다.
뽑기가 게임의 축인데, 그 판정을 내 손을 떠나 플레이어 PC에 맡기는 셈이다.

가챠만 문제가 아니었다. 이런 것들도 로컬에만 있으면 의미가 없다.

|               | 로컬에만 있을 때                        |
| ------------- | --------------------------------------- |
| **계정**      | 기기를 바꾸면 모은 오브가 사라진다      |
| **랭킹**      | 내 점수만 보인다. 그건 랭킹이 아니다    |
| **소유 정보** | 어떤 오브를 가졌는지 증명할 방법이 없다 |

## Unity Gaming Services (UGS)

Unity가 제공하는 백엔드다. **서버를 직접 세울 필요가 없다.**

고른 이유는 세 가지였다.

- **WebGL에서 돌아간다** - 배포 목표가 브라우저였으니 이게 안 되면 후보에서 빠진다
- **서버를 따로 세울 필요가 없다** - 인프라를 직접 관리할 여유가 없었다
- **어차피 Unity로 개발 중이었다** - 같은 생태계 안에서 패키지만 추가하면 된다

혼자 만드는 게임에서 서버 운영까지 떠안는 건 부담이 컸다. 그 부분을 통째로 넘길 수 있다는 게 컸다.

쓴 패키지는 이렇다.

```
com.unity.services.authentication   3.7.2   로그인
com.unity.services.cloudcode        2.10.3  서버 로직
com.unity.services.cloudsave        3.4.1   플레이어 데이터
com.unity.services.economy          3.5.3   재화(GEM)
com.unity.services.leaderboards     2.3.4   랭킹
```

### 패키지만 깔아선 안 된다 - 콘솔에서 제품 켜기

여기서 한 번 걸렸다. 패키지를 다 설치했는데도 호출이 안 됐다.

UGS는 **에디터와 콘솔 양쪽에서 작업해야 한다.**

```
Unity 에디터                       Unity Cloud 콘솔
─────────────                     ─────────────────
패키지 설치                        프로젝트 생성
프로젝트 연결(org / project ID)     제품 탭에서 서비스 활성화
코드 작성                          Cloud Code 스크립트 배포
                                   Economy 통화·리더보드 정의
```

콘솔에 들어가서 **제품(Products) 탭**에서 쓸 서비스를 하나씩 켜야 한다.
Authentication, Cloud Code, Cloud Save, Economy, Leaderboards — 패키지를 깔았다고 자동으로 켜지지 않는다.

> **패키지 설치 = 클라이언트가 말을 걸 준비**
> **콘솔 활성화 = 서버가 들을 준비**
> 둘 다 되어야 통한다.

그리고 켜는 것만으로 끝나지 않는 서비스가 있다.

[Unity Console](https://cloud.unity.com)에 접속하여 필요한 서비스를 실행해 주어야 했다.

![Unity Console 화면](https://hw-blog.s3.ap-northeast-2.amazonaws.com/SubjectNull/unity-console.png)

| 서비스             | 콘솔에서 추가로 할 일                |
| ------------------ | ------------------------------------ |
| **Cloud Code**     | 서버 스크립트를 직접 올려야 실행된다 |
| **Economy**        | GEM 같은 통화를 콘솔에서 먼저 정의   |
| **Leaderboards**   | 리더보드를 만들고 ID를 발급          |
| **Authentication** | 쓸 로그인 방식(익명·Google) 켜기     |

코드에서 부르는 이름들이 전부 **콘솔에 먼저 존재해야 한다.** 통화 이름 하나, 리더보드 ID 하나가 안 맞으면 런타임에서야 터진다.

가챠에 사용되는 스크립트 같은 경우 Cloud Code 서비스에 JS 스크립트를 등록해야했다. 해당 기능으로 특정 ID에 GEM을 추가하는 스크립트 등을 만들어 관리자가 게임을 관리하기 위한 기능들도 추가할 수 있었다.

마지막으로 에디터 쪽에서 **프로젝트를 연결**해야 한다. 이게 안 되어 있으면 어느 프로젝트로 요청을 보낼지 모른다.

### 로그인 - 익명 먼저

```csharp
await AuthenticationService.Instance.SignInAnonymouslyAsync();
```

가입 절차 없이 바로 플레이할 수 있다.

> 계정부터 만들라고 하면 그 자리에서 나가는 사람이 많다.

일단 들어와서 해보게 하고, 나중에 Google 로그인을 붙여서 **게스트로 놀다가 원할 때 계정에 연결**할 수 있게 했다.

## 서버 권위 - 이 편의 핵심

원칙은 하나다.

> **중요한 판단은 전부 서버에서 한다.**
> 클라이언트는 호출하고 **결과를 연출할 뿐이다.**

가챠 서버 코드 첫 줄에 이걸 적어뒀다.

```
클라는 결과 marbleName으로 SO를 찾아 연출만. RNG/재화/소유는 전적으로 서버.
```

### 서버가 하는 일

```
① GEM 100 차감
② 등급 추첨
③ 그 등급에서 오브 하나 추첨
④ 이미 가진 것이면 → 조각으로 환산
⑤ 소유 목록에 추가
```

이 다섯 단계가 **한 번의 서버 호출** 안에서 끝난다. 중간에 끼어들 틈이 없다.

클라이언트가 받는 건 `marbleName` 하나뿐이다. 그걸로 ScriptableObject를 찾아서 연출만 재생한다.
화려한 뽑기 연출은 **이미 결정된 결과를 보여주는 애니메이션**일 뿐이다.

### 재화도 잠갔다

GEM은 Economy의 통화로 두고, **플레이어가 직접 증감하지 못하게** 접근 권한을 막았다.
서버 로직만 건드릴 수 있다. 클라이언트에서 GEM을 더하는 코드는 아예 통하지 않는다.

### 서버 스크립트 9개

Cloud Code에 올린 스크립트다.

```
GachaPull            뽑기
ExchangeMarble       조각으로 오브 교환
GetProfile           프로필 조회
GetGemPackages       상품 목록
CreatePaypalOrder    결제 주문 생성
CapturePaypalOrder   결제 확정 + 지급
GetPendingOrder      미완료 주문 조회
GetPurchaseHistory   구매 내역
WithdrawPurchase     청약철회(환불)
```

뒤의 다섯 개는 결제용이다. **그 얘기는 다음 편에서.**

## WebGL - "에디터에서 되니까 되겠지"가 안 통했다

브라우저에서 돌리려면 WebGL로 빌드해야 한다.
여기서 걸린 건 **에디터에서는 멀쩡한데 빌드에서만** 드러나는 것들이었다.

### ① `Task.Delay`가 안 돈다

**WebGL에는 스레드가 없다.** `await Task.Delay(1000)` 같은 걸 쓰면 그냥 멈춘다.

서버 응답을 기다리는 코드가 여기 걸렸다. 프레임 단위로 기다리는 헬퍼를 만들어 다섯 군데를 바꿨다.

```csharp
public static async Task WaitSignedInAsync(float timeout = 10f)
{
    float deadline = Time.realtimeSinceStartup + timeout;
    while (!IsSignedIn && Time.realtimeSinceStartup < deadline)
        await Awaitable.NextFrameAsync();
}
```

스레드를 재우는 대신 **다음 프레임까지 양보하는** 방식이다.

### ② 압축 설정

빌드 크기가 있어서 Brotli로 압축하고, **압축 해제 폴백**을 켰다.

```
webGLCompressionFormat: 0        Brotli
webGLDecompressionFallback: 1    폴백 켬
```

폴백을 켜면 `Content-Encoding` 헤더를 안 보내는 서버에서도 돌아간다. **서버 설정에 신경 쓸 필요가 없어진다.**

### ③ `runInBackground`

이것도 켰다. 탭을 잠깐 벗어나도 **서버 통신이 끊기지 않는다.**

UGS를 붙인 게임이라 이게 중요했다. 탭을 옮긴 사이에 통신이 죽으면 그 사이 호출이 전부 날아간다.

## 배포 - Netlify

빌드 결과 폴더를 통째로 올리면 끝이다.

```bash
netlify deploy --prod --dir=Builds/WebGL
```

### 드래프트 배포가 유용했다

`--prod`를 빼면 **추측할 수 없는 임시 주소**가 나온다.

```
실 사이트   subjectnull.netlify.app
드래프트    6a7ac463...--subjectnull.netlify.app
```

실제 유저는 계속 이전 버전을 하고, 새 버전은 임시 주소로 혼자 확인한다.
특히 **휴대폰에서 테스트할 때** 이게 아니면 방법이 마땅찮았다.

### 커스텀 템플릿

Unity 기본 템플릿 대신 직접 만들었다.

- 게임 화면이 창 크기에 맞춰 **16:9로 유지**되게
- 파비콘
- 전체화면 버튼

### 주소가 생기고 나서

처음 배포가 끝나고 주소를 열었을 때 든 생각은 이거였다.

> **이제 이 게임을 다른 사람한테 보여줄 수 있겠다.**
> 남들이 직접 플레이해보고, 피드백도 받을 수 있겠다.

내 PC에서만 돌 때는 "만들고 있다"고 말로 설명하는 게 전부였다. 근데 주소가 하나 생기니까 그냥 링크를 던지면 된다.
설레는 마음으로 친구들한테 바로 뿌렸다.

[1편](/blog/게임_개발_도전기_01)에서 친구들이랑 게임하다가 "이건 어떻게 만드는 거지" 싶어서 시작한 건데, 그 친구들한테 내가 만든 걸 보내게 됐다. 게임을 좋아하는 친구들에게 피드백을 받으며 불편한 점, 답답한 부분, 추가되면 좋을 것 같은 기능들 등 조언을 구하여 업데이트 해 나가고 있다.

## 정리

- UGS는 **패키지 설치와 콘솔 활성화가 따로다.** 제품 탭에서 켜야 비로소 통한다
- 통화 이름·리더보드 ID처럼 **코드가 부르는 건 콘솔에 먼저 존재해야 한다**
- 확률·재화·소유처럼 **조작되면 안 되는 판단은 전부 서버로.** 클라이언트는 연출만
- 가챠 연출은 **이미 정해진 결과를 보여주는 애니메이션**이다
- 로그인은 **익명부터.** 가입 절차는 진입 장벽이다
- WebGL에는 스레드가 없다. `Task.Delay` 쓰는 코드는 전부 **프레임 대기로** 바꿔야 한다
- 압축 폴백과 `runInBackground`는 켜두자. **서버 통신하는 게임이면 특히**
- 배포 후 검증은 **드래프트 주소**로. 실 유저를 건드리지 않고 모바일까지 확인할 수 있다
